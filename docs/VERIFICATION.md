# Local verification — 2026-11-02

Python 3.14.7 on Windows, offline model and PayPal simulator. No real payment credentials, model credentials or user data were used. The results below are from the working copy after the rescore fixes (next section), run in this order on one machine.

- `python -m unittest discover tests`: **602 passed**, zero failures or skips.
- `python qa/e2e_demo.py`: **113 checks passed, 0 failed**, in real Edge with phone-sized emulation. Includes purchases, approval and capture, refunds, invoice stops, two-device guardian decisions, unknown-outcome recovery, AG Grid filter/export, offline receipt verification, phone widths, the back button, one-tap freeze, keyboard focus on the card, and a story at 320x640: the zero on the first screen, the Care signing button inside the card, the dock resting on the navigation, the failure drill without sideways scroll, and plain words with Try again when the network is cut; since the rescore also a request while the Care invite is open, the card's main button leading to its question at 390x844 in Care mode, and a browser in one time zone with the server configured for another. No CSP violations or JavaScript errors were reported. Phone results are emulation, not a real phone. 200% text was simulated by setting the page's root font size, not through a browser setting.
- `python eval/run_eval.py --require-all`: 94 of 94 scripted cases passed, no fallback runs, all 31 lab attacks blocked. CI now uses `--require-all`, so a failing scripted case fails the build. `python eval/run_contract_eval.py`: 8 of 8 fault scenarios passed. These are fixed local examples, not a model benchmark or independent security audit.
- Money regressions cover exact decimal parsing, wrong currencies, missing payout amounts, crash/restart before a webhook commit, a cancel or family "no" during the PayPal call, a second payment on one bill, a small payment before a large one, and replacing a paired guardian.
- Mutation spot-check: 23 hand-picked changes to the safety code, one at a time, against the unit suite. 21 were caught. The other two (the told-to-buy gift card pattern; a frozen world outliving idler ones) survived, so those tests were tightened, and both changes are now caught. This is a sample we chose, not a coverage measure.

Reviewed screenshots in `docs/images` were retaken from the current UI by running the demo script's scenes without video, because the video encoder (ffmpeg) isn't installed on this machine. `scripts/capture_demo.py` itself, with video, was not re-run here: its silent footage from an earlier commit no longer matches the UI and must be re-recorded. Rescore fixes (an independent rescore, reproduced first in the running keyless app, each with a regression test that failed before the fix):

1. Classic scripts. "The IRS called, I owe 1500 or I'll be arrested, pay them" got "I heard two possible amounts"; the lottery-fee and online-stranger scripts were asked for a payee; "Grandma it's me Ben, I lost my phone, wire me 900" froze payments. Four script families (government or tax threat, prize or inheritance fee, someone known only online, family impersonation on a new or borrowed phone) now stop before any card, with the hotline; the scan runs before the amount questions, and "1500 or I'll" is one amount. `tests/test_classic_scams.py` checks the reported sentences, 17 new phrasings and 8 benign look-alikes that must still reach a normal card.
2. After a scam alert, "Stop that payment" was refused as a new payment and the open card stayed signable. Cancelling the open card now comes before every gate and really cancels it (signing afterwards fails, nothing reaches PayPal); stopping an unclaimed payout stays allowed, signed, with the alert shown; "call my daughter" and the hotline get a plain answer. New payments are still refused. `tests/test_after_alert.py`.
3. Without RULE_FIXED_HOUR the night rule used America/New_York while the greeting used the browser's clock. The browser now sends its zone name; the server accepts only a valid IANA name (never an hour) and falls back to CUSTOMER_TIMEZONE. `tests/test_timezone.py` looks up, at run time, a zone where it is night and one where it is day, so it doesn't pin the hour; the browser run checks the same with a mismatched server zone.
4. In Care mode on a phone the card's question sat below the fold under a disabled "Answer the question first". The button now stays pressable, never signs, and brings the question into view with focus on its answers (browser run, 390x844).
5. With the Care invite open, "Can you send Anna $50 please" was read as yes. Only a plain yes or no answers it; anything else is handled as a request and the invite waits on screen. `tests/test_care_mode.py`.
6. "Lost my phone" anywhere froze every payment. A lost or stolen phone, wallet or purse now gets one question first; "freeze my payments" said outright still freezes at once. `tests/test_lost_phone.py`.

Changed test expectations in the rescore fixes: the phone story picked "the first choice" after asking which grandson; the Care invite now stays open above those buttons, so it picks a grandson button by its label and checks there are two. The browser run's servers now start on free ports in 7100-7999 (an OS-assigned port, 1719, was one the browser refuses). The ruleset version is now rules-2026.11.02-v9. Two browser checks failed once each in full runs and passed on rerun without changes (the stop's story in the Activity grid right after clearing the search; the offline message in the 320 px story); they are timing-sensitive, not fixed here.

Changed test expectations in the design round: column filters open behind "All columns and filters", so the browser run clicks that first; typing in phone Care mode opens behind Type, so its helper taps that first; a session with no rows now shows one plain line and no zero totals, so that check was rewritten (stops being counted in a pinned row is still checked in the Activity story); a cut network is now an expected console message in the browser run. Earlier wording changes: the simulator says "The simulator confirms" instead of "PayPal confirms", and a stopped request says "I can't do this one." instead of "I can't process this:". No test was skipped. A fork-time rewrite of `tests/test_recovery.py` (one bill posting once became "can't overdraw") is unchanged; the original behaviour is tested again in `tests/test_abuse_limits.py` with plenty of allowance, so only the invoice check can refuse.
